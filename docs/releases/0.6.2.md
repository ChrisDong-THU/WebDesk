# WebDesk 0.6.2

修复 0.6.1 点击“接收到本机”即出现 `A file selection is already open` 的回归。该提示并不一定表示有文件窗：`Win32Window::Create` 会先调用 `Destroy`，进而触发派生类 `OnDestroy`。0.6.1 将选择器作为常驻成员，在创建窗口前已执行其永久关闭逻辑。

选择器现在由 Flutter 引擎生命周期拥有：引擎成功创建后初始化，销毁时取消并释放；成员销毁顺序保证撤销回复时引擎仍然有效。原生窗口不可用与已有选择操作使用不同的错误类别。文件窗继续在独立 STA 中运行，并保留会话归属、定向取消及有界并发。

文件窗与主窗口的关闭卡顿有共同机制：系统窗口交互的原生消息循环可能影响同线程上的远控分发。处理原则一致，但职责不同。主窗口由应用管理，标题栏处理保持非阻塞，关闭遵循托盘隐藏规则；系统文件窗使用独立 STA 保持远控分发畅通，关闭应返回取消结果。本次“已有窗口”异常属于生命周期错误，而非标题栏阻塞。

新增 `scripts/test-file-selection.ps1` 集成门禁，运行实际 FlutterWindow / Win32Window 和原生方法通道。覆盖首次打开、关闭后再次打开、取消、旧会话隔离及断线取消，并检查文件窗打开时 Dart 心跳继续运行。该入口不使用桌面服务、屏幕采集或输入注入；启动前验证测试程序为 asInvoker。正式发布在门禁后重新清理构建输出并构建 `lib/main.dart`，验证生产程序的管理员清单。

安装 0.6.2 后修复才会生效。此前 Windows 独立选择器与网页取消状态回归仍保留；Mac Chrome 公网远控场景需在更新客户端后复测。

发布验证：Node 94/94、Flutter 98/98，静态分析与格式检查通过；正式构建内的真实 Flutter 文件窗门禁四个场景均通过，并验证测试与生产程序各自的执行级别。生产入口为 `lib/main.dart`。公网服务已更新到 0.6.2 / 协议 1，网页哈希、认证、信令和结束清理核验通过；安装器与部署记录见本地 `flutter-release/0.6.2/`。
